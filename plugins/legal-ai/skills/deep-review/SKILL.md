## 技能描述
协助用户将本地合同（Word/PDF）上传到远程法务审查引擎，自动解析签约主体与法域，基于用户选定立场执行大模型深度风险审查，并渲染结构化审查报告。

## 前置条件（首次使用必读）

### 1. 授权与凭证

本服务认证统一走 **OAuth 2.1（授权码 + PKCE）**，凭证完全由宿主 MCP 客户端管理。本节描述与具体宿主无关，适用于任何实现了 MCP 授权规范的 Agent。

- **不配置、不索取、不硬编码凭证**：MCP 连接配置中不应出现 `headers.Authorization`、`${VAR}` 占位符或任何密钥；也不要让用户手工粘贴 Token。
- **MCP 工具调用无需关心凭证**：用户在宿主里完成一次「连接/授权」（选择工作空间）后，宿主会在每次 MCP 请求自动注入 `Authorization: Bearer <access_token>`，并在过期时用 `refresh_token` 自动续期重试，全过程对 Agent 透明。
- **文件上传/下载也不带凭证**：合同字节量级决定了它不能经 MCP 工具传输（base64 后单份文档即6 万级 token），因此改由出票工具 `acquireUploadTicket` / `acquireDownloadTickets` 返回**带一次性票据号的相对路径**：身份与用途存在服务端，路径里只带一个不可猜测的票据号，拼上 `<BASE_URL>` 就能直接 curl。本技能**不读取也不依赖**宿主本地的 Token 缓存文件。
- `<BASE_URL>`：取宿主 MCP 配置中本服务 `url` 的**协议 + 域名**部分，即丢弃从第一个单斜杠开始的整个路径（如 `https://<服务域名>/mcp` → `https://<服务域名>`）。本服务可能有多个对外入口（测试/生产/客户专属域名），**只有这里推出的域名才是用户实际连的那个**，服务端下发的路径不得自己另猜域名。
- 错误分两类，处理方式不同：MCP 工具报未授权/`401` 时，引导用户在宿主连接器上重新完成授权，**不要重试请求**；报票据无效/`403`/过期时，重新调用出票工具拿新路径即可，**不要去找用户**。

### 2. MCP 服务器配置参考（客户端 mcp.json）
```json
{
  "mcpServers": {
    "legal-ai": {
      "url": "https://<服务域名>/mcp"
    }
  }
}
```

> 服务端点只有一个 `/mcp`，认证全走 OAuth 由客户端自动注入，**禁止**在此添加 `headers.Authorization` 或任何密钥。
> 部分宿主需额外声明传输类型，写法因宿主而异（WorkBuddy 为 `"type": "streamableHttp"`，Qoder 为 `"type": "streamable-http"`，有的可省略或由 `url` 推断），以目标宿主文档为准。

> 出票工具返回的是**相对路径**（已含网关前缀与一次性票据），用法固定为 `<BASE_URL>` + 返回路径；域名只从上面第 1 节的规则推出，**不要猜其他域名，也不需要 Authorization 头**。

## SOP 执行工作流

整体工作流分为五个标准阶段：
**文件出票与直传（MCP 出票 + HTTP 传字节） ➔ 获取选项并确认（MCP） ➔ 发起审查（MCP） ➔ 轮询等待（MCP） ➔ 渲染报告（Markdown）**

---

### 阶段一：上传文件（先出票，再直传）

1. 从用户对话中提取本地文件路径（如 `/Users/name/Desktop/采购合同.docx`），仅支持 `.docx` 和 `.pdf` 格式。
2. 本地取文件实际字节数（macOS：`stat -f%z 文件`；Linux：`stat -c%s 文件`；Windows：PowerShell `(Get-Item 文件).Length`）。
3. 调用 MCP 工具 `acquireUploadTicket(fileName, fileSize)` 获取直传路径：返回的 `path` 字段已含一次性票据，**5 分钟内有效、仅能使用一次**。注意 `fileName` 必须等于本地文件的**文件名部分（basename）**，服务端会校验上传名与出票名一致。
4. 在本地终端静默执行 curl 直传（`<BASE_URL>` 按第 1 节从宿主 MCP 配置推出；文件流直传，不占用大模型上下文 Token；**不要**附加 `Authorization` 头）：
   ```bash
   curl -s -X POST -F "file=@{filePath}" "<BASE_URL>{票据path}"
   ```
5. 解析返回的 JSON（上传接口将文件存储到 S3，返回 fileId）：
   ```json
   {
     "success": true,
     "fileId": 1234567890,
     "fileName": "采购合同.docx",
     "error": null
   }
   ```
6. 若 `success=false`，直接将 `error` 信息提示用户并**终止流程**（常见原因：格式不支持、文件过大、文件名与出票不一致）。
7. 若上传本身报错（票据过期/已被使用/网络中断）：重新调 `acquireUploadTicket` 换一张票据再传，**最多重试 1 次**，仍失败则终止并提示。

---

### 阶段二：获取审查选项并等待客户确认（MCP）

1. 上传成功后，立即调用远程 MCP 工具获取从合同中解析出的主体与配置建议：
   ```
   acquireReviewOptions(fileId=<fileId>)
   ```
   返回示例：
   ```json
   {
     "success": true,
     "taskId": 123456,
     "stances": ["甲方：XX科技有限公司", "乙方：YY贸易有限公司", "中立第三方视角"],
     "jurisdictions": ["PRC"],
     "languages": ["中文 (zh)", "英文 (en)", "日文 (ja)"],
     "error": null
   }
   ```
   > 注意：docx/doc 格式的合同，云端会自动启用可编辑模式，允许后续对条款进行在线修改。
   若 `success=false`，向用户展示 `error` 并终止流程。

2. **必须暂停并等待用户回复**，按照如下模板向用户展示选项：

---
📄 **已成功加载合同：** `{fileName}`
经云端初步解析，为您推荐以下审查偏好：

**1. 请确认您的审查立场：**
- [1] {stances[0]}
- [2] {stances[1]}
- [3] {stances[2]}
- *（如不符合，您也可以直接输入具体立场，例如："我是第三方担保人" 或 "代表丙方"）*

**2. 请选择适用法域（仅支持以下 5 种）：**
- [A] 中国大陆法（PRC）
- [B] 中国香港法（HK）
- [C] 美国法（US）
- [D] 日本法（JP）
- [E] 其他地区/通用外国法（GENERIC_FOREIGN）
- 默认推荐：`{jurisdictions[0]}`

**3. 请选择报告语言（仅支持以下 3 种）：**
- [a] 中文（zh）
- [b] 英文（en）
- [c] 日文（ja）
- 默认推荐：`zh`

👉 *您可以直接回复："选1，法域按默认，语言中文"，或"全部默认"，也可以自定义回复："我是乙方，法域选 HK，报告要英文"*
---

#### 规则与映射硬约束（必须严格遵守）

1. **默认值规则**：
   - 若用户回复“全部默认”或未明确某项偏好，立场默认取 `stances[0]`，法域默认取 `{jurisdictions[0]}`（云端法域识别结果），语言默认取 `zh`。
   - 若 `jurisdictions` 为空，法域兜底传 `GENERIC_FOREIGN`（与接口空值默认行为一致）。

2. **法域映射（传给接口的 `jurisdiction` 只能是这 5 个字符串之一）**：
   | 用户表述 | jurisdiction 传参值 |
   | :--- | :--- |
   | 中国大陆法 / 中国法 | `PRC` |
   | 中国香港法 / 香港法 | `HK` |
   | 美国法 | `US` |
   | 日本法 | `JP` |
   | 其他地区 / 无法确定 / 国际通用法 | `GENERIC_FOREIGN` |
   | 用户说"默认"（未指定） | 取 `{jurisdictions[0]}`（识别结果），不是固定 `PRC` |
   - *拦截规则*：若用户提出不支持的法域（如"英国法"、"新加坡法"），不得随意传参，应提示用户："当前深度审查仅支持中国大陆、中国香港、美国、日本及通用外国法，其他法域建议使用通用外国法（GENERIC_FOREIGN）"，待用户确认后继续。

3. **语言映射（传给接口的 `language` 只能是这 3 个字符串之一）**：
   | 用户表述 | language 传参值 |
   | :--- | :--- |
   | 中文 / 汉语 / 默认 | `zh` |
   | 英文 / 英语 | `en` |
   | 日文 / 日语 | `ja` |
   - *拦截规则*：若用户提出不支持的语言（如"法语"、"韩语"），提示用户："当前报告语言仅支持中文、英文、日文"，引导用户选择后继续。

---

### 阶段三：发起审查任务（MCP）

1. 收到用户回复后，整理出最终的 `stance`、`jurisdiction` 和 `language`。
2. 向用户发送提示并给出时间预期：*"已确认立场为【{stance}】，云端法务大模型正在逐条审阅合同漏洞与履约风险，预计需要 3-8 分钟。我会自动轮询进度，完成后第一时间通知您，您可以先做其他事情。"*
3. 调用远程 MCP 工具发起审查：
   ```
   executeDeepReview(taskId=<taskId>, stance=<立场>, jurisdiction=<法域代码>, language=<语言代码>)
   ```
4. **核心注意事项**：
   - 该工具**幂等**：任务待启动时执行启动并立即返回 `status: "IN_PROCESS"`；已在进行中时直接返回 `IN_PROCESS`（不重复启动、不重复扣费）；已完成时直接返回审查报告；
   - 发起成功后**立即转入阶段四**；
   - 若直接返回 `status: "FAILED"`，展示 `error` 并终止流程。

---

### 阶段四：轮询查询审查结果（MCP）

1. 直接复用阶段三的 `executeDeepReview` 轮询状态：
   ```
   executeDeepReview(taskId=<taskId>)
   ```
   返回结构：
   ```json
   {
     "status": "IN_PROCESS | SUCCESS | FAILED",
     "taskId": 123456,
     "error": null
   }
   ```
   > 审查完成（`status: "SUCCESS"`）后取文件：按阶段五调一次 `acquireDownloadTickets` 换全套一次性直下路径，
   > 本阶段不拼任何下载域名、也不携带 `Authorization` 头。
2. **轮询策略**（先长后短、低噪输出）：
   - **首次长等待**：任务发起后静默等待 **5 分钟**，然后第 1 次调用 `executeDeepReview` 查询状态；
   - **后续短轮询**：若仍为 `IN_PROCESS`，之后每次静默等待 **2 分钟**再调用，最多再查 **3 次**（即第 2、3、4 次查询）；
   - **静默等待**：等待期间仅执行 `sleep` 命令，**不要**向用户展示等待命令细节（如命令行输出），也不要在轮询之间输出任何中间过程文案；
   - **低噪输出（关键）**：轮询返回 `IN_PROCESS` 时**严禁**逐条向用户输出"审查进行中，继续等待"等相同文案——连续多轮相同回复会触发模型重复回复检测导致流程中断。仅在以下时机输出内容：
     - 任务发起后的首次确认（阶段三已覆盖，不再重复）；
     - 第 1 次查询后（约 5 分钟）轻量同步一次进度（如"审查已进行约 5 分钟，仍在深度分析中"）；
     - 状态变为 `SUCCESS` / `FAILED` 时立即汇报结果（**汇报完就结束本轮**，不自动转入下载，按阶段五硬闸门等用户指令）。
   - **超时熔断**：总计 4 次查询（5 分钟 + 2 分钟×3 = 11 分钟）后若仍为 `IN_PROCESS`，停止轮询并提示用户："合同篇幅较长，云端仍在深度分析中，您的任务ID为 {taskId}。您可以稍后让我查询审查结果，我会自动继续轮询"；**并在本轮对话中记住 taskId**，用户后续询问时直接复用，无需重复提供；

---

### 阶段五：展示结果并下载文件

> #### ⛔ 本阶段硬闸门：必须先停下等用户，不得自动下载
>
> 审查完成与下载文件是**两轮事**：本轮只输出下面的完成信息模板并**结束回复**，收到用户明确指令（如“下载”“保存”或指定目录）后，下一轮才允许执行本阶段后面的出票与下载步骤。
>
> - **在用户回复前禁止调用 `acquireDownloadTickets`，禁止执行任何 curl / `download_files.py`**；也**禁止**在同一轮里既展示清单又把文件下完。
> - “默认下载到桌面”只回答“**存到哪个目录**”，**绝不**意味着“可以不问就下载”；省掉的是路径询问，不是下载确认。
> - 用户在对话开头一次性说过“帮我审查并下载”不算本轮的下载授权：合同成品会直接落盘，先让用户看一眼审查结果再写盘。
> - 部分宿主 Agent 自动执行倾向很强（倾向于不等确认就把剩下的步骤一口气做完），本闸门与宿主无关，必须严格执行。

当 `executeDeepReview` 返回 `status: "SUCCESS"` 时，向用户展示审查完成信息与可下载文件清单（展示完就结束本轮，等用户指令）：

---
📋 **合同智能审查已完成**
- **任务ID**：`{taskId}`

以下文件可供下载：
- 📎 合同原文（Word/PDF）
- 📎 审查报告（PDF）

默认下载到桌面，回复"下载"即可；如需其他路径，直接告诉我（如"下载到 /Users/name/Documents"）
---

（输出到此为止，本轮不要再调用任何工具或执行命令）

**收到用户明确的下载指令后**，调**一次** `acquireDownloadTickets(taskId)`：服务端按场景**一次返回全部交付文件**的一次性直下路径（深度审查固定两份：`fileType=original` 为含批注的合同文档、`fileType=report` 为审查报告 PDF），交付几份由服务端场景定义决定，本工具一次给全，**不需要**按文件类型多次调用。

返回结构（`path` 是相对路径，域名由 `<BASE_URL>` 提供）：
```json
{
  "bizScene": "deep_review",
  "taskId": "123456",
  "expiresInSeconds": 600,
  "tickets": [
    { "fileType": "original", "path": "/assistant-api/mcp-file/download?ticket=..." },
    { "fileType": "report",   "path": "/assistant-api/mcp-file/download?ticket=..." }
  ]
}
```

再把 `tickets` 里每一项拼成 `<BASE_URL>{path}` 后一并交给与 SKILL.md 同目录的外部 Python 脚本 `download_files.py`，下载到指定目录（默认桌面目录：macOS/Linux 为 `~/Desktop`，Windows 为 `%USERPROFILE%\Desktop`）。

**文件重命名规则**：若目标目录已存在同名文件，自动在文件名后添加序号后缀（如 `销售代理合同2_1.docx`、`销售代理合同2_2.docx`），避免覆盖。

下载命令（几个文件一次调用，脚本内部并行下载；**不需要 Token 参数**）：
```bash
python3 <SKILL.md所在目录>/download_files.py \
  {保存目录,默认桌面目录} \
  "<BASE_URL>{tickets[0].path}" \
  "<BASE_URL>{tickets[1].path}"
```

- 脚本逐行打印每个文件的最终保存路径（已处理重名冲突与服务端文件名），Agent 据此展示给用户；
- 下载失败时脚本向 stderr 输出具体原因并返回非零退出码（`403` 表示票据无效或已被使用、`404` 表示报告未生成）；
- **每张票据都是一次性的**：要重试下载必须重新调 `acquireDownloadTickets` 拿全套新路径，禁止用同一个地址重放。

3. 下载完成后向用户展示：

---
✅ 文件已下载至 `{保存目录}`：
- 📎 合同原文：`{服务端返回的文件名，如 销售代理合同1.docx}`
- 📎 审查报告：`{服务端返回的文件名，如 审查报告-xxx.pdf}`
---

## 异常处理速查表

| 异常场景 | Agent 应对策略 |
| :--- | :--- |
| MCP 工具报未授权 / 401 | 宿主侧 OAuth 失效：引导用户在宿主连接器上重新完成授权，**严禁死循环重试** |
| 用户未回复就要下载文件 | 阶段五是硬闸门：输出完成信息后必须结束本轮，等到用户明确说“下载/保存”才出票与执行命令 |
| 上传/下载返回 401、403 或票据过期 | 票据无效、已过期或已被使用（一次性）：重新调用 `acquireUploadTicket` / `acquireDownloadTickets` 拿新路径再试一次，不要去读任何宿主 Token 缓存、也不要求用户操作 |
| 上传/下载返回 404 或域名不存在 | 域名拼错了：`<BASE_URL>` 只能从宿主 MCP 配置里本服务 `url` 的协议+域名部分截取，不得自己猜测 |
| 上传接口返回 `success: false` | 提示上传失败及具体 `error` 原因，终止流程 |
| 上传报"文件名与出票时声明的不一致" | 用本地文件的 basename 重新出票（出票与上传必须同名） |
| 文件格式非 `.docx` 或 `.pdf` | 上传前本地直接拦截并友好提示，不发起网络请求 |
| MCP 工具返回 `status: "FAILED"` | 展示具体的失败原因 `error`，终止流程 |
| 用户提供未支持的法域/语言 | 根据硬约束规则拦截并友好引导，待用户确认合规值后再继续 |
| 下载报告返回 HTTP 404 | 审查报告 PDF 生成失败，仅展示合同原文下载结果，并告知用户报告生成异常 |
| 模型回复重复检测被触发 | 轮询期间连续输出相同文案所致；按阶段四"低噪输出"规则：IN_PROCESS 不逐条汇报、进度同步文案差异化、仅状态变化时输出 |
