# Connector 依赖说明

本插件是**多个法务技能（Skill）的集合**，插件内全部技能共用同一个 BestSign Legal AI MCP Server（Streamable HTTP 端点）与同一套 OAuth 2.1 授权体系，**只需授权一次**即可使用所有技能。

## MCP 服务器

宿主 MCP 配置中声明的服务器：

| 名称 | 默认地址 | 说明 |
| --- | --- | --- |
| `legal-ai` | `https://mcp-legal-jp.bestsign.com/mcp` | Legal AI MCP 服务（生产环境） |

> 服务器名 `legal-ai` 代表整个 Legal AI 服务（不局限于某一个技能），与插件同名。
> 该名称在三处必须保持一致，改其一必改其余：
>
> 1. 宿主 MCP 配置里 `mcpServers` 的 key；
> 2. 各 `SKILL.md` 中推导 `<BASE_URL>` 时引用的服务名（本服务 `url`）；
> 3. 本说明表的名称列。
>
> 注意：Token **不来自连接配置**（连接配置里没有 `headers`），而是由宿主自己的 OAuth 缓存持有；
> 该缓存按**端点 URL 的哈希**归键（实测 key 为 `endpoint:` + `sha256(url)`），
> 同一 URL 的多个服务器名共用一份授权。因此**改名不会掉授权**，只有 URL（域名或路径）变化才需重新授权。

## 授权方式

- 端点走 **OAuth 2.1 授权码 + PKCE** 流程：首次连接时宿主会自动弹出授权页面，
  选择要授权的工作空间并确认后，客户端自动管理 access_token / refresh_token，
  **无需**在连接配置中手写 Authorization 头或粘贴 Token。
- 若接口返回 `401`，请重新完成授权，不要重试请求。

## 传输类型声明

服务端点走 Streamable HTTP。**部分宿主需要在连接配置里显式声明传输类型，写法因宿主而异**（有的用连字符、有的用驼峰、有的可省略或由 `url` 推断），以目标宿主文档为准。本插件的通用内容源不固定该写法，由各宿主壳在构建时注入。

## 切换环境

测试 / 开发 / 生产环境仅域名不同，安装后可在宿主的 MCP 配置中替换 `url` 的域名部分，
路径保持 `/mcp` 不变，例如：

```
https://<服务域名>/mcp
```

## 本地已有配置冲突提示

若你在宿主的全局 MCP 配置中已经手动配置过同一端点（无论服务器名是什么），
安装本插件后可能出现两个指向同一服务的连接，表现为工具列表重复
（授权仍共用，因为 Token 按 URL 归键）。建议在插件安装测试通过后二选一保留：
用插件分发（升级跟随插件），或继续用手动配置（从插件配置中移除 `mcpServers`），
不要两者并存。
